# 可视化工作台

工作台只调度 VR＋原生 Seed-VC 推理，不加载融合训练代码。所有模型和路径在服务器配置，浏览器负责输入、乐谱核对、进度与试听。

## 启动

先完成 [运行指南](QUICKSTART.md) 的模型与环境准备，然后在调度环境安装界面依赖：

```bash
.venv-svc/bin/pip install -e '.[ui]'
cp configs/web.example.json configs/web.local.json
# 按本机修改 web.local.json 的路径
.venv-svc/bin/utaweave serve --config configs/web.local.json --port 8770
```

浏览器打开 `http://127.0.0.1:8770/`。远程部署可在自己的电脑执行 `ssh -L 8770:127.0.0.1:8770 USER@SERVER`，再访问本机同一地址。服务默认只监听回环地址；这是个人本地工作台，没有多用户账户系统，不应直接开放到公网。

`web.local.json` 的路径相对于配置文件解析：

| 字段 | 用途 |
| --- | --- |
| `workspace` | 上传、任务记录和结果；每个任务独立目录 |
| `render_config` | 现有 VR、LoRA、固定导唱参考、TiFA、Seed 配置 |
| `reference_runtime` | 人声分离、去混响、SingMOS 环境 |
| `annotation_config` | Vocal2Midi 模型位置与标注参数；任务会覆盖输入、输出和 BPM |
| `labeling_python` | 安装了标注依赖及 `pyopenjtalk` 的解释器；混合英文还复用标注配置中的 TiFA 字典与 ONNX G2P |
| `netease_bridge` | 本仓库 `scripts/netease_bridge.cjs` |
| `netease_api_module` | 已安装网易云 API 模块的 `main.js`，需提供 `login_status` 和 `song_url_v1` |
| `credential_file` | 可选，仅服务器读取的 Cookie 文本文件路径；不在页面填写或上传 |

当前机器使用现有 NeteaseCloudMusicApi 4.28.0 模块，本仓库只提供适配器，不包含该模块、登录凭据或采集数据库。沿用已经配置好的模块即可；没有该模块时仍能上传本地原曲/参考、读取歌词链接和使用 MIDI。音频导入会检查完整文件与账户可用状态；获取失败时显示错误，不以试听片段冒充完整歌曲。

需要关掉 SSH 后继续提供页面时，可以用 `tmux` 运行上述服务，或使用已有进程管理器。推理任务作为独立进程启动，关闭浏览器或断开 SSH 不会中断已提交任务；机器重启仍会中断。重开页面可以从“最近任务”恢复显示。

## 有原曲

1. 输入网易云歌曲链接，或上传本地音频，填写 BPM。链接会提供原曲音频和歌词；本地音频也可以配上歌词链接/文本。
2. 点击“准备乐谱”：分离人声与伴奏，运行音频自动识别、TiFA 对齐和 GAME 音符提取。
3. 查看音符预览、歌词原文和逐单元读音。这里显示的是自动标注，不是人工真值。网易云歌词作为核对依据，不会未经对应就覆盖音频标注。
4. 可以修正每个单元的假名读音，音符与时间保持不变。需要修改旋律时走 MIDI 入口；当前表格不是完整的音符拖动编辑器。
5. 选择目标音色，确认乐谱后生成。

BPM 目前需要用户提供。人声分离、歌词识别和对齐仍可能有错误，界面不会把“自动处理完成”标成“乐谱准确”。

## 只有 MIDI 和歌词

1. 上传 `.mid` / `.midi`，选择单声部旋律轨。打击乐轨不参与；所选轨中存在复音会被拒绝，不能把钢琴和弦当成歌声旋律。
2. 粘贴日语歌词或 LRC，也可以从网易云链接读取；MIDI 已有歌词事件时可直接导入。
3. 有两行及以上 LRC 时间戳时，先转换每句读音，再结合时间、休止和读音数量，整体匹配句子与 MIDI 音符范围；之后在句内自动分配。署名和元信息不进入读音。空白时间戳保留为句尾，因此间奏不会自动填歌词。同一时间戳的不同文本会报错，需保留原文、移除并列翻译；混合了无时间戳正文时也需先整理。
4. 使用“按句对齐歌词”，优先检查标记的句子。可以修改整句读音、补全省略的歌词、调整首尾音符编号，再“应用本句读音 · 保留手动音符”；包括本句在内，已经手工改过的音符会保留，需核对它们是否符合新读音。句子不能重叠，扩大范围前先缩短相邻句。简略重复句可用“按原读音重复填满”生成待保存草稿，但它并不识别原唱的实际重复次数。未归属任何句子的音符暂设 `SP`，界面列出这些范围，需检查是否真的是间奏。
5. 整体错位时展开时间设置：`MIDI 秒数 = 原 LRC 秒数 × 时间比例 + 时间偏移`，正偏移使歌词向后移动。自动估计在首音符与首句差值附近 ±12 秒搜索偏移，并搜索 0.95–1.05 的比例；人工可设置 ±300 秒、0.5–2 倍。LRC 的常量 offset 标签包含在拟合后的总偏移中，不会额外叠加。整体重排覆盖逐音符调整，但保留已保存的各句读音；提交前的草稿会保存在任务的 `alignment-history/`。
6. 需要时打开“逐音符微调”。填写日语假名或英文单词；一个音符可填多个拍音（如 `きみ`）。一字多音时，首音符填读音，后续连续音符填 `-`，不能跨休止延音。分离的音符可明确填元音续唱；不演唱的音符填 `SP`。英文保留为词，使用已有 TiFA 英文字典和 ONNX G2P 生成 `en/` 音素，避免日语前端把词逐字母拼读；唱法、断词仍需试听。
7. “试听旋律”播放前 30 秒，按句按钮播放本句旋律，均为检查音高节奏的合成音，不是 VR 演唱。可下载含标准 MIDI `lyrics` 元事件的文件；原有音符、轨道和速度事件保持不变，导出编码为 UTF-8。
8. 展开“生成切分”并点击“预览生成切分”，检查每段的歌词、罗马音、原曲位置和时长。预览使用当前逐音符歌词和已应用的句子范围，不覆盖编辑，不调用 GPU；修改读音后需重新预览。核对后选择参考音色，再生成演唱。伴奏可选，不需要原始人声录音。仍有整句读音未分配时会阻止生成，不能仅改一个音符来绕过。

每句标题、读音编辑框和逐音符表会同时显示罗马音，方便不认识日文的使用者核对。罗马音取自当前假名读音，长音使用 `aa`、`ou` 等明确拼写，英文单词保留；`SP`、`AP`、`-` 分别提示休止、换气和延音。假名编辑即时更新，新增汉字需先应用本句、生成读音后更新。这些提示只用于显示，不会替换生成与导出的日文歌词，也不是中文翻译。

不会输入日文时，可使用默认的“日语罗马音 · 自动转假名”模式，整句和逐音符编辑都支持。输入 `kimi` 会预览 `キミ`，`gakkou` → `ガッコウ`，`shin'you` → `シンヨウ`；可以按拍音加空格，单独的促音输入 `xtsu`。混合英文用花括号标明，例如 `kimi {tick tack}`，保存后只有假名和英文词进入原有流程，花括号不会演唱。`SP`、`AP` 和单独的 `-` 在逐音符输入中仍是原有控制符。若要直接填写英文或日文，切换“日文 / 英文原文”；切换模式本身不修改已分配的歌词。未完成或无法识别的拼写会标红，需修正后提交；整句读音自动保存为草稿；需要更新自动分配时点击“应用本句读音 · 保留手动音符”。

纯文本没有句级时间依据，仍使用顺序分配草稿，并显示空项或未分配读音；超额且未经修改的草稿不能提交生成。LRC 也只提供句级时间，不提供音节时刻，因此“全部已分配”不等于“全部唱对”。自动匹配没有使用原唱音频，无法保证歌词版本相同、每个字音准确或旋律轨完全正确；版本不同、自由速度、哼唱省略等情况仍需核对。当前主要支持日语及其中混合的英文，中文自动读音尚未支持。

MIDI 的 tempo map 用于计算真实秒数；VR 的离散音符类别按支持的整数 BPM 近似量化。超出 1–255 的速度先做倍速/半速记谱换算，例如 278 BPM 转为 139 BPM，并根据原始秒数重新量化拍值；原 MIDI、音高和实际起止时间不变。变速作品会显示提醒。加载 GPU 模型前会检查条件时长，实际 VR 提示还会核对 BPM 标记，避免上游静默回退到 120 BPM。

MIDI 生成直接按音符时间和已应用的 LRC 句界规划，优先保留完整乐句，不再把每个 250 毫秒的音符间隙当成独立唱句。**每段的实际演唱跨度，以及量化后含首尾留白的 VR 条件时长，都不超过 8 秒**。过短的相邻句尽量合并；长句在歌词单元之间至少 75 毫秒的音符空隙处拆分。不跨音符或延音单元裁切，不自动改变音符时值，也不删除句内休止。独立短句可保留，避免跨长间奏合并。

已确认的句界可使用更短的音符空隙（至少 4 毫秒）；装配时按真实对齐到的非歌词区间缩短淡入淡出，仍禁止侵入歌词主体。无法满足时长与切点条件时，在加载模型前报错，应在 MIDI 编辑器中检查超长延音和句间休止。没有 LRC 句界时按 MIDI 音符间隙规划，不凭空推断语义整句。原曲音频入口沿用原有的音频停顿规划与 14.5 秒内容上限。

8 秒约束针对输入片段和模型条件。VR 使用原生停止生成，实际原速音频时长仍可能有所偏差，后续继续做对齐检查与有限变速，不为满足时长强行截掉歌词。切分算法变化会更新导唱缓存标识；旧试听文件不会因此自动变成新结果。

如果 MIDI 的短音符导致句内频繁停顿，可在“生成切分”中启用**减少句内短休止**。仅将同一 LRC 句内、相邻有歌词音符之间自动产生的 75–300 毫秒 `SP` 转为前一个音高的延续，合并同音高拍值，并保持每个后续歌词的条件起点与总条件时长不变。句界、长休止、独立 `SP`/`AP` 音符和切片边界保留；无 LRC 句界时不自动处理。这个选项只改变送入 VR 的演唱条件，原 MIDI、逐音符编辑与 MIDI 导出不变。预览会显示处理数量，生成请求与检查记录会保存开关值；默认关闭。这是连唱处理，并不能保证模型不会产生气声。

为了容纳生成前后余量，首音符不足 0.5 秒时整条时间轴会补足到 0.5 秒，末尾留 1.5 秒；可选伴奏按同样偏移对齐。MIDI 模式创建的静音时间轴缓冲只提供整曲长度与导出时间轴，不用于寻找切点，不是原始人声，不进入 VR/Seed 的声学条件或响度匹配。

## 自动保存与恢复

核对乐谱时，每次输入先写入浏览器本地草稿，停止输入约 0.8 秒后自动同步服务器。拼写不完整、暂时为空的输入也会保留。状态栏区分“本机已保存”“已保存到服务器”与保存失败；断网会重试同步。如果两处都写入失败，页面会提示下载备份，并在离开时警告。

- **保存草稿**只保存整句读音、逐音符修改、首尾范围、输入模式和参考设置，不运行重新分配，也不生成演唱。
- **下载备份**保存完整的 JSON 草稿，可在“恢复其他草稿 / 导入备份”里恢复；文件保留未完成的原始拼写。
- **下载含歌词的 MIDI**使用当前逐音符歌词。即使有整句草稿尚未应用，也可以导出；未应用的整句文字不会混入 MIDI。音符读音本身必须有效。
- **应用本句读音**更新该句自动分配，保留相对旧自动分配已经改动的手工音符。保存逐音符修改无需点击此按钮。需应用的整句有标记和跳转入口。

重新打开同一任务会恢复同版乐谱的最近草稿。不同窗口分别存储，不会互相覆盖正在编辑的输入；可从恢复列表选择其他窗口的记录。服务器乐谱版本变化时，当前编辑先保留，旧版草稿需要手动选择恢复；不同乐谱无法混用，冲突音符会提示而不是自动覆盖。整体重排仍是显式的重算操作，会替换逐音符分配，执行前应下载备份。

浏览器本地草稿随来源地址保存，转发端口变化或清空浏览器存储会影响本地恢复；已经同步的服务器草稿保存在 `workspace/jobs/JOB_ID/drafts/`，仍可跨端口恢复。此功能覆盖乐谱核对与参考设置，不包括“准备乐谱”之前的输入表单，也不备份尚未上传的本地文件。旧版本已打开的页面不会自动获得新代码，请先复制未提交的内容或完成备份，再在新标签页打开新版本。

## 音色参考与生成

仍然只有两种处理方式：

- 手动：上传 1–25 秒已经剪好的单人清唱，保持片段本身，不重新评分。
- 自动：使用原曲、另一首网易云歌曲或上传的完整音源，分离、连续切片，再平衡 SingMOS 音质和有效人声时长。

VR 的固定导唱参考仍来自服务端 `render_config.guide_reference_run`；目标参考交给 Seed-VC。界面默认沿用可用流水线的 Seed 30 步、CFG 0.7，可以在生成设置中调整。

模型推理任务串行使用 GPU，MIDI 解析和读音准备不占用 GPU 队列。进度显示实际阶段，以及 VR 提供的已生成句数；不以动画代替真实完成度。停止按钮终止该任务进程组；失败后可查看日志、修改读音/参考并重新生成。相同音符与设置可复用导唱缓存。

## 结果与文件

完成后提供混音、纯人声和原速串联试听，支持拖动、唱句跳转及切换音轨保留位置。MP3 用于整曲预览，原生 WAV 保留供下载。所选参考单独显示，并在自动模式下展示 SingMOS 分数。

`workspace/jobs/JOB_ID/` 保存准备后的乐谱、原文、参考选择、推理配置、阶段日志与导出结果。`score.vr.json` 和带歌词的 MIDI 可以单独下载。浏览器只可访问任务内允许的媒体/报告文件，不提供配置或任意服务器文件下载。公开 Git 仓库不包含上传、Cookie、原始歌曲或生成结果。
