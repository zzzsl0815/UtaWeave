# 流水线设计

## 目标与输入

首版目标是日语单主唱整曲再演唱：音符、歌词与节奏贴合原歌，音色由独立参考指定，句间衔接自然。它通过离散乐谱重新生成演唱；原歌的连续 F0、颤音、气声和细微力度不是全部受当前 VR 条件直接控制，不能承诺逐帧复刻。

输入：本地歌曲音频；原语言歌词，优先有时间的 LRC/YRC；可选对应罗马音／假名；目标音色参考。允许直接提供主唱、伴奏或已编辑的乐谱，以跳过已完成步骤。没有可靠歌词的纯音频自动转写列为后续能力，首版不依赖重新下载 ASR。

默认保留完整歌曲的所有唱句。训练集的质量筛选、时长筛选、歌手类别筛选不能原样套到整曲推理：低分段要标记、换分离设置或允许替换输入，不能悄悄从演唱中消失。用户提供的虚拟歌手演唱也可作为转谱输入，不沿用训练采集时排除虚拟歌手的条件。

有时间戳的歌词即使与歌名完全相同，也作为演唱内容保留。SingMOS只记录分数，不决定是否删句；失败句保留原文、时间和失败状态，不能以缺句结果宣称整首完成。标注覆盖率和音高／读音准确性分别记录。

## 各阶段契约

| 阶段 | 输入 | 持久化输出 | 失败与复用 |
|---|---|---|---|
| 导入 | 音频、歌词、可选读音 | 源文件哈希、采样率、时长、歌词来源 | 不依赖采集平台数据库；给定本地文件即可建任务 |
| 分离 | 全曲混音 | 保持全曲时间轴的主唱、伴奏、重建误差 | 可以直接提供 stems；不能把切片拼接误当作原始时间轴 |
| 对齐准备 | 原语言歌词、读音 | 句时间、候选读音及选择来源 | 有罗马音时先核对同一句来源与时间族；歧义保留记录 |
| 音素对齐 | 歌声、读音候选 | mora／phone 绝对时间与对齐诊断 | TiFA 分数只作诊断，不能证明歌词或边界真实正确 |
| 提取音符 | 歌声、mora 边界 | 实测音高／起止时间、mora 所属关系 | ROSVOT 首版；VP、GAME 等是可替换后端，不是既定真值 |
| 编译乐谱 | 实测时值、BPM／tempo map | 标准 score、VR 条件、MIDI／TextGrid | 原始秒时值与模型量化时值分别保存；不覆盖实测时值 |
| 参考准备 | 指定参考文件 | 参考窗口、源区间、模型特征及哈希 | 首版沿用已验证的约6–8秒清晰单人歌声；8秒优先 |
| 分句规划 | 乐谱、源歌声、呼吸候选 | 分句内容、上下文、切点、归属 | 无安全切点时给出原因，不能从单词或呼吸中间硬切 |
| 合成 | 每句乐谱、同一音色参考、VR／LoRA | 完整原生输出、种子、组批信息、EOS 原因 | 自然 EOS；只局部重做坏段，不延长停止下限补齐 |
| 输出对齐 | 原生输出、原乐谱 | 生成音素边界、漂移与完整性诊断 | 不能仅把音频长度拉到一样就判为完整 |
| 衔接／混音 | 合格片段、伴奏 | 新人声、混音、未经拉伸的人声、审计 | 真实生成空隙优先；保留原始输出和先前版本 |
| 试听 | 所有产物与诊断 | 静态试听页、接缝定位、版本对照 | 页面被动刷新；媒体支持 Range 和版本化缓存 |

## 单一时间轴

统一以输入全曲音频起点为0秒。每次裁切、去前置静音、重采样、滤波或延迟补偿，都记录输入区间、输出起点、采样率和偏移；不能只修改秒数而保留冲突的旧采样索引。

所有局部对齐转回全曲时间，乐谱再按句编译成模型条件。BPM 及来源需要记录；没有可信 BPM 时可以估计，但要检查半速／倍速与量化误差。自由速度歌曲的 tempo map 保留在中间格式，当前 VR 固定 BPM 条件如何分段近似属于待实现能力，不能把所有歌曲硬套成一个速度。

旧《テルーの唄》记录有18处约0.38秒的时钟差异。现有导入显式选择原试听所用的秒时间，并保存矛盾字段的审计；这不作为可推广的固定补偿。新适配器需要查明变换来源或重新对齐后生成一致的时钟。

## 读音与乐谱完整性

匹配的原语言歌词＋所给罗马音／假名优先；缺失时才走 Kashi 候选与音频对齐选择。处理长音、促音、拨音、助词读法及一 mora 多音符；英文混合句需要显式语言／读音支持，不能忽略英文字母继续出“完整”乐谱。

英文词使用本地英文词典／LSTM G2P和TiFA英文音素；已有英文歌词时直接使用，没有必要重复ASR。已有识别结果也可作为文本输入。日语罗马音按同源同句匹配后优先采用，不因另一候选声学分数较高就更改，也不加入歌曲专用改读规则。当前整曲功能试验保留原标注模型，并使用上述覆盖策略；尚未做成通用CLI的一键转谱入口。

每个歌词单位必须有音符覆盖，且音符不能指向压缩后错位的单位。零宽单位、未知 token、音符缺失、重复／漏字分别记为问题，不以补造很短的音素或最近音高来掩盖。现有实验的 nearest-note 修补仅作为有来源的旧产物导入，首版新标注不默认将这种填补视为可靠音高。

原音符按中点归属可能漏掉很短的歌词单位，编译时按音符与原单位的实际时间交集保留条件。没有实测音高的单位仍保留并标记未知／清音，不借相邻音符填成“已确认音高”。覆盖完整不代表这些位置已经准确。

缺失音高可自动补全：先查单位范围内的连续RMVPE F0，再以独立pYIN估计交叉检查；短清音或尾音可在不跨休止的有限邻域内继承发声音高。实测恢复与邻域推断分开记录，推断保留低置信标记。静音、模型明显分歧和缺少局部证据时保留未解决状态。补全另存版本，歌词、罗马音、音素时值和已有音高保持不变，不能把补音高当成修好了歌词或对齐。

保留 `score.raw.json` 和编译后的 `score.vr.json`，并记录量化改变了多少时长。标准乐谱是后续编辑入口，不在合成脚本里维护歌曲专用的18句数组。

## 音色参考与模型预设

音色参考是独立输入，不从训练数据库强制挑同名歌手。优先采用清楚、单人、无截断、有效演唱占比高的窗口，参考特征固定后全曲复用。约6–8秒为当前已验证范围；更长的8–15秒先单独验证后端上下文与效果，不能仅改时长就当作默认有效。

SingMOS 可作参考选择的辅助；没有分数仍允许使用指定参考。高音质分数不能证明音色身份或克隆相似度。原曲较差的分离音质与参考质量需分开记录。

当前已试听预设是 r64 第五轮，Base LM=1、Residual LM=1、LocDiT=0.5；这不是所有 LoRA 都乘0.5。各系数、checkpoint、基座与模块兼容性均可配置，禁止把当前192个 LoRA 模块的数量断言当作所有模型的通用要求。

## 分段、EOS 与呼吸

当前案例采用约6–14秒演唱内容的短句，作为首版起点，不硬编码18段或固定歌词行数。优先按乐句、完整 mora、源歌声的真实安静区切分。源歌声和生成歌声的呼吸位置会不同，生成后的衔接需要重新检查。

呼吸是独立事件，状态区分“未标注／自动检测／已核对”。很轻的吸气不能只按人声峰值百分比判成静音。一次呼吸只能归属一边，尽量让下一句保留完整的吸气，并保留上一句连续尾音；不在呼吸中间做长交叉淡化。AP 等模型 token 必须确认后端支持才导出，不能把保存了呼吸事件等同于模型已经受到呼吸控制。

找不到安全切点时，依次尝试调整到相邻完整乐句、增加有限上下文重叠、在安全边界重做失败局部。上下文属于正常乐谱内容，生成仍使用原生 EOS。已有实验表明强制延迟停止会出现崩坏，不采用设置长 `min_len` 的办法修补短输出。

重叠上下文尚未实现。实现时需要保留两侧完整输出、在生成后的安静区选交接点，并保证歌词不重复。没有安全交接的片段必须报告，不能直接叠加两个演唱或切掉半个字。

已有呼吸修复 v3 复用原生输出，在实际片段间隙连接，并在音素保护区之外平滑边缘气声；它是启发式修复，不是可靠的呼吸识别器，也不能还原模型已经缺失的呼吸。

## 生成、对齐与局部重做

原生人声始终保留。伴奏跟随模式可轻微伸缩时间以匹配原曲，另输出不拉伸的人声用于比较。时长偏差大时先检查漏字、重复、错音符和节奏，不扩大拉伸比例强行贴合。

只重做失败句，记录有限次尝试、种子及拒绝原因。更换种子或分句比强迫模型继续输出更适合当前情况，但效果仍需试听。分句变更后，仅失效受影响的合成和后续衔接缓存。

复现记录包含 checkpoint／LoRA／参考哈希、模块系数、CFG、扩散步数、精度、随机种子、批内顺序、batch大小、模型和代码版本。相同 seed 在不同组批方式下仍可能生成不同结果，不能只记录 seed 后称为同条件比较。

## 调度、缓存与质量检查

先完成单曲顺序版。分离／标注与 VR 后端用各自解释器和进程，路径放本地配置，避免混装依赖与跨阶段残留显存。确认正确后，再复用已有跨歌曲流水调度。多首任务的失败互不牵连。

缓存键由输入内容、有效配置、模型版本和代码版本组成，复用前校验输出哈希与数量。一次歌曲任务分阶段恢复，修改配置生成新版本。用不可变原始输出和审计支持局部重做，不以“文件存在”判断成功，也不覆盖原始候选。

自动检查只解决结构完整性与明显故障：漏句、重复单位、时间错位、未知 token、非有限值、削波、长度上限、异常时长变化、接缝是否碰到受保护音素／呼吸。它们不能证明音色自然或演唱好听。首版以用户试听验收，不建设复杂评测服务，也不用自训 VP 作唯一裁判。
